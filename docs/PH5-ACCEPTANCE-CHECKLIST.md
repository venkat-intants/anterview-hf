**Notes.**
- **Small groups.** A rate, median or mean whose population is under 5 is marked *too few to compare*. Pipeline figures keep their value: a rate still shows its numerator and denominator, and a rate, a median and a mean each show the withheld figure on hover. Check-in coverage, retention and performance values are blanked below 5 — nothing on hover either — and for retention and performance the numerator is blanked too. When any group's retention or performance is blanked, it is blanked in every group, so it cannot be recovered by subtraction.
- **Live figures.** Definitions are frozen; figures are recalculated from the records each time, so they can move when a record does (an offer withdrawn after a hire).
- **Only the current version is calculated.** Every past version stays identifiable in the lock and in `GET /hr/metrics/definitions`, and a figure resolves its own version; the glossary lists the versions in force. Calculating an old version side by side would need `compute.py` extended, when the first version 2 is published.
- **Meaning changes** from the pre-PH5 roll-up, each stated in the metric's change note: *interviewed* now means an AI interview completed or a human scorecard submitted (not the ledger status, and no longer an AI scorecard alone — which is what the HR console's Interviewed tile used to count); *sat exam* no longer counts another application's exam, and now also counts an assessment recorded with no exam attempt behind it; *hired* counts only hires that stand; *time to hire* counts only hires that stand and starts at the application's `created_at` rather than the ledger's first move to `new`, which some applications never had. The console's Interviewed and Exam-taken counts, and the pipeline panel's bars, follow these definitions now, so both can read higher than before.

**Notes.**
- **Markers are asked for, not guaranteed — the one thing this story does not close.** The prompt asks the model to mark a claim `[S1]` and to leave reasoning unmarked. The server ENFORCES only the negative half: a marker naming a ref the run never issued is stripped, counted and logged. A model that writes no markers at all produces a perfectly acceptable answer with an accurate source strip and no per-claim attribution — which is why lines 4 and 5 are ⚠️ and not ✅, and they are not claimed as solved. The `cited_refs`/`invented_refs` counters in the `agent.chat.answered` audit row are how a bad `GROQ_MODEL` would be spotted; nothing alerts on it today.
- **`CITATION_ROUTES` now describes what the code emits.** It did not when this wave was first assessed: roughly two of twenty call sites used it and the rest agreed with it by luck, including one that did not (`workflow_tools` emitted `/hr/requisitions/{id}/workflow` for a `job` citation while the table said `/hr/requisitions/{id}`). Every href across the four citation-producing modules is now built by `citation_href`/`citation_href_for_role`, with legitimate deep links declared in a `CITATION_VIEWS` table (a workflow canvas, a decision queue, each console's own analytics dashboard, and a document's two consoles) and an undeclared `(kind, view)` raising rather than silently falling back. One named exception passes through: the evidence graph's anchored link, whose `?enrolment=` and `#section` the table cannot express.
- **Four citation chips used to lead to the 404 page** — `applicant`/`scorecard`, `interview`, `exam_attempt` and `document`. Each now has a route that opens the record, and `citationRoutes.test.ts` matches every template against the routes `App.tsx` declares, using react-router's own matcher. That also repaired every **Open** link on the evidence trail, which was 404ing for the same reason, and the `exam_attempt` citation now names the attempt rather than its exam.
- **Two links still cannot land on the record, and say so instead of pretending.** A HUMAN panel interview is cited with the same `interview` kind as an AI invite, and no HR screen lists panel sessions — the chip lands on the AI-interview list with a sentence naming the candidate's own record as the place to look. And the candidate drawer's `#section` anchor does not scroll, because its sections mount as their queries resolve.
- **The exam-attempt resolver costs 1 + N requests** (one per exam, until the attempt is found), because no endpoint resolves a bare attempt id. It is a rescue path off a citation chip, its queries share the keys the destination screen uses, and the cheap fix — one `GET /hr/exams/attempts/{id}` — is written down in the file.
- **The untrusted-data notice was missing in production until this wave.** `UNTRUSTED_DATA_NOTICE` was applied only in `build_wire_messages`, which no production adapter calls, so `SAFETY_CLAUSE` was telling the model to distrust a block that never appeared on either provider's wire. Both adapters now go through one `tool_wire_content`, with a per-adapter test on the serialised body.
- **A citation label is untrusted input.** An `applicant` citation's label is the candidate's own name off the public apply form, and the `SOURCES` line is the first thing that ever put a label in front of a model. Each field is stripped of invisible characters, has four structural homoglyphs folded, has `|`, `[`, `]`, `·` and newlines neutralised, and is capped — and the line drops WHOLE entries rather than truncating mid-entry, so what the model can cite and what the UI shows never disagree silently.
- **One deliberate UX change:** the attention panel's citations were inert `<span>`s that discarded a real href. They are links now.

**Notes.**
- **Erasure cannot reach inside a document, and that is AR-8, not an oversight.** There is no key from an applicant to a chunk of an HR-uploaded PDF, nor to the original file in object storage. All four tables sit in `EXCLUDED_TABLES` with the reasoning written out, the limit is AR-8 (owner `platform_owner`, three triggers) and it is disclosed in `docs/DATA-FLOW.md`, which the consent modal links. The compensating controls — upload attestation, `hr_only` default for an HR manager's upload, and an immediate purge that includes the original file — are mitigations, not detection. This is the one line in the story that is not ✅, and it is not a gap anything in this wave can close.
- **`RETENTION_DRY_RUN` defaults to `true`**, here as everywhere else in this service: until a deployer flips it, the nightly tick counts what it would purge and deletes nothing. Retrieval exclusion does not depend on it — a deleted document's content is gone in the request, and an expired one leaves the query on its date — but content retention does.
- **A document cannot change what the system DOES. It can change what the model SAYS.** The structural layers (no write effect, context-derived tenancy and audience, role-derived toolset, no corpus text on any drafting path) are what line 15 rests on, and the last of those now examines all six drafting handlers instead of the zero its name filter used to match. Fencing, the untrusted-data notice and `detect_injection` are likelihood reduction and degrade with model quality. Nothing in this wave claims otherwise, and nothing should.
- **The screen has a way in now.** **Documents** appears in the HR navigation (with the other reference material, after Offer templates) and in the super admin's, each pointing at its own console's path because `/hr/*` admits `hr_manager` only. Before that entry existed the screen was reachable only by typing the URL, which is why five lines here were ⚠️ on the first pass.
- **Cut this wave:** registering a URL as a source (SSRF surface; upload only), OCR for scanned PDFs (`no_text` fails cleanly instead), in-browser preview (download through a 5-minute signed attachment link only, an AR-6 isolation control), reranking and per-tenant hybrid tuning, and any localisation — chunking and the lexical leg are `to_tsvector('english')`, as applicant search already is, so a Hindi or Telugu handbook still embeds and still matches semantically while only its keyword leg degrades.
- **Cost.** Corpus embedding is a one-off per document plus ~20 tokens per copilot query; it is not on the ₹12 per-interview-session line and does not move it. Bounded by four config caps (10 MB, 400k chars, 400 chunks/document, 200 documents and 20,000 current chunks per company) plus the carry-over-unchanged-chunks optimisation. The rupee rate itself is **unverified** — `gemini-embedding-001` is recorded as free-tier and no paid rate has been confirmed from Google's published price.
- **Degraded mode is visible, not silent.** With no `GEMINI_API_KEY` reachable, upload still works, versions park at *Indexing…* and search falls back to keywords — announced by `semantic: false`, a `degraded` note to the model, a banner on the screen and `corpus_semantic` on `GET /agent/status`. The equivalent failure for applicant search is still entirely silent; unchanged here.
